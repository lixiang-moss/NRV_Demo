# 移植后性能测试与瓶颈分析

> 历史记录：该文对应旧的 100 ms/Python 桥版本。当前修改与真机结果见 [E2FAI 修复与真机短测](E2FAI修复与真机短测.md)。

2026-09-12 · 短期演示验收 · 基线 12fe7f9

## 交付结论

E2FAI 完整算法已接入当前工程，Qt 主窗口支持勾选 1–4 路画面。保留原适配器时间映射、过滤规则及参数操作；模型在宿主机 GPU 运行，接收未经过软件过滤的事件。未实施性能优化。

按用户最终要求，停止重复矩阵和长时间压力测试。本报告采用已经完成的必要功能检查、约 20 秒移植后真机运行，以及停止前已完成的一轮短回放。未完成的第二轮基线不参与结论；没有进行 10 分钟稳定性测试。

**演示能启动并出图，但不能宣称已达到稳定实时运行：旧时间映射存在大幅正跳，ROS 事件批次也存在间断。程序会清理循环状态，避免把不连续输入当作连续序列。**

## 链路与测量口径

RAW 同时进入适配器和官方 renderer；适配器发布 `/dvs/events`，分别进入原 Python 过滤支路和新增桥。桥通过本机 TCP 送给宿主模型，结果经 `/nrv_e2fai/result` 回到 Qt。驱动、适配器、renderer 共用 nodelet manager；原 Python、桥、Qt、宿主模型分别运行。Qt 仍按 100 ms 定时刷新最新图像。

源码定位：`dvs_adapter_nodelet.cpp:217,281` 保留时间映射和 RAW 回调；`demo.py:84,135` 为过滤与出图；`e2fai_bridge.py:167` 为新桥入口；`e2fai_worker.py:203` 为推理会话；`gui.py:356,378` 为接收与刷新。对应目录为 `ros_ws/src/nrv_demo/src`、`ros_ws/src/nrv_demo/scripts` 和 `examples`。

阶段耗时用单调时钟；已验证宿主与容器时钟命名空间一致。GPU 前向用 CUDA events；CPU 等待 GPU 输出的耗时与前向重叠，不能相加。下面的回调到控件时间，从最后一个贡献事件批的桥回调开始，到 setPixmap 返回结束，不是传感器到显示器的物理延迟。

同一份 RAW、相同原生 960×720、100 ms 窗口、软件过滤关闭。每个已完成配置只运行一遍，预热 10 秒后统计 60 秒；速率按时段内状态首末差分计算。相机录制共 85.45 秒、5,894 个包，录制中 RAW 序号间断为 0。

| 配置 | 原 Python 处理事件/秒 | 原算法出图 FPS | 模型结果接收 FPS |
| --- | ---: | ---: | ---: |
| 原版两画面 | 389,542 | 5.77 | 不适用 |
| 移植后无 GUI | 377,627 | 5.52 | 2.24 |
| 移植后 1 画面 | 374,683 | 5.47 | 2.22 |

四画面开启测量时，原 Python 吞吐较关闭时低约 2.9%，但模型结果率反而略高。仅一次对照，不能把差异全部归因于埋点，也不能宣称开销为零。默认关闭测量。

## 能确认什么

1. **时间语义异常，证据明确。** 20 秒原始回放的 RAW 包头跨度为 19.986 秒，但观察到单批事件跨度最大 4,294.980 秒，大跳接近 32 位微秒计数的完整周期。事件保持单调也不代表时间尺度正确。具体成因仍需核对解码器与相机时间字；本次未修改映射。
2. **模型原生分辨率前向超过窗口周期，证据明确。** GPU 前向约 121 ms，已经超过 100 ms，还未计入转图与通信。10 窗口/秒的合成联调曾触发有界 FIFO 过载暂停；这是联调观察，不是完成了长时间压力测试。
3. **ROS/Python 入口存在接收能力限制，位置尚未完全分解。** 四画面回放中，原 Python 和桥进程各约占一个逻辑核。桥识别到 209 次 ROS 序号间断，推断缺少 2,516 条已发布事件消息；这些是整会话累计，不能当作 RAW 丢包。回调前反序列化、传输与排队尚未分别计时。

同次回放整体 GPU 利用率均值约 30.5%、显存峰值约 2.73 GiB，包含桌面进程。低平均 GPU 利用率不否定单次前向慢：输入间断和状态重置也会使 GPU 等待。只有短时内存记录，不据此宣布无泄漏或长期稳定。
