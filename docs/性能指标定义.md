# 移植后的性能测量口径

本文定义各埋点的测量口径。埋点本身不改变事件顺序、时间映射、过滤规则、队列策略或旧 summary 字段的含义；运行所采用的功能与性能方案另由该次配置记录说明。

## 开关、时钟和统计

- Python 共用 `PerfRecorder(output_dir, component, enabled=False, interval_s=5, capacity=4096)`；`tick()` 返回 `perf_counter_ns()`，关闭时返回 0；`elapsed(name, start_ns, events=0, **metadata)` 记录毫秒；`observe(name, value, unit='ms', events=0, **metadata)` 记录量值；`increment(name, n=1)` 记录次数；`close()` 写出最后一段。关闭时不创建文件、线程、样本，也不读测量时钟，但仍有函数调用和开关判断成本。
- 启用后每 5 秒由独立线程输出 `performance_<component>.jsonl`；每项指标每段最多保留最近 4096 个样本。每段 `count`、`events`、`sum`、`min`、`max` 覆盖全部观察；`sample_count`、`sample_events`、`overflow` 明确分位数对应的有界样本。P50/P95/P99 用排序后线性插值，溢出时不能称作全时段精确分位数；不同区间的分位数不能直接求平均。
- 同项指标是每批/窗口一次，`events` 为该批输入事件数；生成图像阶段为画布累积的保留事件数。`metadata_last` 仅是该段最后样本的定位信息，不代表该段全部数据。完整事件数量、窗口标识和损失诊断仍由业务 summary/结果元数据提供。
- 每段同时落盘有界的 `samples=[[value, events, sample_ns], ...]`；Python 的 `sample_metadata` 与其一一对应，保留调用者提供的窗口/批次标识。跨段分位数必须合并样本值后重算，不能平均各段 P95；若任一段 `overflow>0`，合并结果仅代表各段保留样本。只有 `overflow=0` 且采样段完全覆盖所报统计时段时，才可称为该时段全部已观测批次的精确分位数。`sample_ns` 是 observe 入场时的同组件单调时钟纳秒值，可按输入起点提供的预热结束/测量结束区间筛选，再合并重算；跨组件使用前核对 Linux 宿主与容器 monotonic 时钟来源/命名空间一致。样本时刻是观测记录时刻，可能比被测阶段终点稍晚，不能解释成源事件时间。第三列不存在的旧结果只能按完整周期选择或明确边缘混入。筛选后事件数只能累加保留样本的第二列，不能复用整周期 events。记录数组增加文件写入量，因此开关对照须使用含样本落盘的最终代码。
- Python `perf_counter_ns()`、C++ `steady_clock` 测的是含等待的墙钟耗时；不能将耗时直接解释成 CPU 计算时间。跨进程绝对值不直接相减，除非验证相同时钟来源/命名空间。本次只移植模型算法，新的 worker 不沿用研究脚本的整帧统计口径：测量 OFF 不额外创建 CUDA events 或调用测量专用 synchronize；测量 ON 在体素后同步，并用 CUDA events 标记前向。有限值检查和结果读取本身仍可能等待 GPU，这是业务数据依赖。ON/OFF 的同步差异必须纳入测量开销对照。
- C++ 适配器以 `~perf_enabled`、`~perf_interval_s`、`~perf_capacity`、`~perf_output_dir` 配置，输出同结构 JSONL；测量不改变当前 group_aer 补丁及固定锚点映射。Python 使用同名 ROS 参数，输出目录默认本次 `~output_dir`。

## 测量边界

| 组件/指标 | 起点 → 终点 | 说明 |
| --- | --- | --- |
| adapter.callback | RAW 回调入场 → 原有统计/日志完成 | 包含解码、构造和发布调用，不含回调前等待 |
| adapter.decode | 调用 decoder decode 前 → 全包 decode 返回 | 包含同步 `eventCD` 回调、逐事件映射与对象构造 |
| adapter.publish | ROS publish 前 → 返回 | 不代表订阅者收到 |
| adapter.raw_packet_age | 回调时 ROS now − RAW header stamp | 未校准的包龄代理量；零时间戳不采样，负年龄另行保留，不是物理端到端延迟 |
| adapter.timestamp_pair | RAW 回调开始的时钟、包头和该包解码完成后的首末事件时间配对 | PERF 开启时每秒最多一次；值为 1、单位 packet，events 为该包解码事件数；所有配对时间以 JSON 整数纳秒存于同一样本 metadata |
| demo.objects_to_arrays | 四个 fromiter 前 → 完成 | 输入对象已由 rospy 反序列化 |
| demo.filter | filter.apply 前 → 返回 | 保留现有跨批历史及过滤规则 |
| demo.mask_select | 对保留掩码索引前 → 完成 | 包括新数组分配 |
| demo.canvas_lock_wait | 请求画布锁前 → 取得锁 | 回调侧 |
| demo.canvas_lock_hold | 取得画布锁 → 原有更新完成 | 回调侧，不含新增统计记录操作 |
| demo.event_callback | 事件回调入场 → 画布锁释放 | 非空批次，含以上阶段及中间测量开销 |
| demo.image_lock_wait/hold | 请求锁 → 取得锁 / 取得锁 → 复制清空完成 | 图像生成侧 |
| demo.draw | 画布快照取出 → 文本/标记绘制完成 | 不含锁内复制 |
| demo.image_message | Image 构造前 → tobytes 完成 | 不含 ROS 序列化后的发送 |
| demo.image_publish | publish 前 → 返回 | 非显示完成 |
| demo.image_total | 图像生成函数入场 → 原有计数更新完成 | 非空画布 |
| demo.parameter_fetch | 每轮读取 ROS 参数前 → 返回 | 不改变参数查询频率 |
| bridge/host | 完整接收、数组转换、入队/出队、组窗、体素、前向、渲染和结果发布边界 | 在对应组件记录显式阶段名；队列等待与计算分开，保留窗口/会话定位信息 |
| worker.voxel_build | voxelize 前 → ON 模式体素 GPU 同步返回 | CPU 处理、传输与 GPU 体素工作整体墙钟时间；OFF 不追加该同步 |
| worker.model_submit | forward_step 前 → Python 调用返回 | CPU 提交墙钟耗时，不代表 GPU 前向完成 |
| worker.model_cuda_forward | 前向前 CUDA event → 前向后 CUDA event | CUDA 流上事件间隔；只在测量 ON 且使用 CUDA 时存在 |
| worker.output_ready_and_finite_check | 输出有限值检查开始 → CPU 得到检查结果 | 包含等待前向 GPU 工作完成与检查本身；与 CUDA 前向区间重叠，**不能把两者相加**计算总处理时间 |
| worker.result_cpu_copy | 推理线程开始取得 CPU 快照 → 灰度和光流 CPU 数组就绪 | 包含必要的设备到宿主同步复制；每个张量仅复制一次，结果线程不使用 CUDA |
| worker.inference_to_cpu_snapshot | 本窗体素构建开始 → CPU 快照就绪 | 推理线程该窗的实际墙钟占用，含体素、提交、输出检查及复制；与这些阶段重叠，不能相加 |
| worker.result_handoff_wait | 首次提交结果 → 成功放入单项 FIFO | 仅 thread 模式；队满时可中断等待，不覆盖结果 |
| worker.result_queue_residence | 成功非阻塞入队尝试前 → 结果线程开始处理 | 仅 thread 模式；起点紧邻实际入队，包含该次成功入队调用的微小开销，不含此前满队列等待 |
| worker.result_cpu_render_and_pack | CPU 结果处理开始 → payload 完成 | 灰度归一化、光流着色、布局转换及 bytes 打包；不含复制、队列等待或发送 |
| worker.result_render_and_pack | result_cpu_copy + result_cpu_render_and_pack | 两模式均保留原“复制及转图打包执行成本”的聚合口径；线程模式是两段耗时之和，不是跨越排队的连续墙钟区间，不能再与其子项相加 |
| worker.result_send | TCP 发送调用前 → 完整发送返回 | thread 模式在结果线程记录；完成不等于 ROS/GUI 已接收 |
| gui | 回调接收 → 定时刷新取图；转图、缩放、setPixmap | setPixmap 返回仅是控件提交，不是显示器呈现 |

`adapter.timestamp_pair` 的 `sample_metadata` 与该指标的 `samples` 一一对应，并共用原有有界容量与周期落盘。字段为 `raw_sequence`（本包 EventPacket.seq）、`raw_header_stamp_ns`、`callback_monotonic_ns`（回调入场的 steady_clock）、`callback_ros_ns`（紧接入场读取的 ROS 时间）、`event_count`、`sensor_anchor_ns` 和 `ros_anchor_ns`。非空包另有 `event_first_ns` / `event_last_ns`（按原始解码输出顺序取首末的映射 ROS 时间）与 `sensor_first_ns` / `sensor_last_ns`（用既有固定锚点逆变换恢复的解码器时间）。首末不是最小/最大值，倒退不会被排序、截断或修正；空包省略首末字段，零包头原值保留。每秒采样的是该时段遇到的一个包，不能据此重建全部包、检测所有逆序或汇总全流事件吞吐。

这些配对可比较解码器时间推进、RAW 包头推进及回调单调时间推进，帮助区分包头之后的积压与映射时钟差异。当前 API 没有直接暴露原始 reference/sub 时间字摘要，本次没有增加第二套 RAW 解码。设备物理时钟、包头生成前的 USB/驱动等待，以及传感器时间单位校准仍是盲区。新增字段只在 PERF 分支中构造，每包原有计时保持，配对 map 每秒最多创建一次；关闭时不为此读取额外时钟或分配 metadata。C++ 旧 `samples` 三列与 `metadata_last` 含义保持不变，只有包含配对信息的指标增添 `sample_metadata`。

表中的 `demo.*` 为已归档 Python 算法支路的历史口径；当前生产 launch 不启动该支路，不应期待本次记录包含这些指标。

GUI 的 `refresh_interval` 为相邻刷新回调开始间隔，`refresh_timer_lateness=max(0, interval_ms-100)` 相对既有 100 ms 定时器衡量延后；`presentations_<key>` 只统计提交到对应控件的次数。`mapped_window_age_at_setpixmap` 为 ROS now 减输出窗口的映射结束时间，允许为负；仅作映射时间异常/年龄代理，绝不能解释成已校准端到端延迟。图像转换与等待指标的 `sample_metadata.source` 区分每路画面，汇总器保留全部来源聚合并另提供分来源行，二者不能重复累加。

Worker 的 `window_complete` 每完成一个输出窗口记录值 1、单位 `window`；附会话、窗口号、源批次范围、窗口起止时间、分辨率、重置原因/次数、`source_callback_ns` 和完成时间。`source_callback_ns` 是**最后一批贡献该窗口事件的桥回调时刻**（`sources[-1]`），不是窗口首事件时刻，也不是传感器物理时刻。`callback_to_result_send` / `callback_to_setpixmap` 的起点按这一口径解释；原始逐窗口元数据保存在 JSONL，报告应保留其可追踪链接。

## 资源与对照

`scripts/monitor_resources.py --output-dir PATH --match PATTERN --duration SECONDS` 每秒扫描匹配进程和其后代，记录进程/线程 CPU、RSS、系统内存/交换及 GPU 利用率/显存。可重复 `--pid` 固定根进程。CPU 100% 表示一个逻辑 CPU 的全部时间；进程 CPU 可超过 100%。首样本没有差分 CPU，记为 null。线程 RSS 与进程共享，不累加。GPU 字段为整卡总量；支持时另采集 GPU 计算进程显存。权限不足/进程退出/工具不可用以 null 或错误记录，不按 0 处理。

测试必须记录代码、权重、环境、相机/过滤参数、输入负载、分辨率、时间窗、抽样上限、GUI 面板数及统计时段。暖机单列。相同确定性输入分别开关测量，比较吞吐、CPU、延迟分布和结果正确性；未测开销不能宣布可忽略。真实运动不可完全重复时报告事件率差异。源分支 A4000 历史数字是引用资料，不是当前 RTX 3060 实测。

## 盲区与解释限制

厂商相机/USB/打包内部、rospy 回调外传输及反序列化、官方 renderer 内部、未设置标记的内核/TCP 等待，以及 Qt 合成/物理显示均不由业务回调埋点直接测到。RAW 序号间断次数、缺失包数、桥接丢弃、模型事件抽样、GUI 覆盖旧图必须分开。没有新事件时图像年龄增长不等于积压。平均 FPS 不能替代新鲜度或已校准端到端延迟。必须结合阶段分布、序号、队列驻留及内存趋势定位，证据不足就列下一项对照实验。
