# E2FAI 250 ms 窗口与结果线程实测

2026-09-12；数据目录：`output/result_thread_250_20260912/`。

后续配置更新：宿主输入 FIFO 已按要求扩为 1 GiB，批数上限仍为 64。下文实测均使用当时的 256 MiB 配置，不代表 1 GiB 容量已完成真机验证。

默认已改为 **250 ms＋单个结果线程**。同一段 10 秒真机 RAW 回放中，250 ms 的线程模式将不含组窗的每窗推理线程占用从约 **152.32 ms 降到 126.42 ms（减少 17.0%）**；输入队列平均驻留从 **38.93 ms 降到 28.08 ms**。两模式均产生 31 个结果，增加的是处理余量，本段输入下未提高结果帧率。

最终 30 秒真机运行输出 **93 个结果**，没有过载暂停或 RAW／ROS 接收序号间断；但结束时仍有 **36 批、约 190.22 MiB** 的输入积压，不能据此宣布持续实时性问题已解决。

## 实施内容

- 启动器、模型入口、组窗默认统一为 250 ms；真实断流阈值仍为 300 ms。原生 960×720、完整事件、15-bin 和顺序 ConvGRU 不变。
- 推理线程完成体素、模型、有限值检查和灰度／光流各一次 CPU 复制；结果线程顺序执行灰度归一化、光流着色、浮点布局转换、打包与 TCP 发送。彩色预览和浮点输出复用同一份 CPU 光流。
- 结果 FIFO 最多放 **一个等待项**，另可有一个正在处理的结果；满时可中断地等待，不覆盖结果、不跳窗。输入 FIFO 仍为 64 批／256 MiB，未扩容。
- GRU 仅由推理线程持有，显示归一化仅由结果线程持有并按重置标识清理。断开先关闭 socket，解除发送阻塞，再退出结果线程、清理待处理结果；新会话不会复用旧状态。
- ROS 话题、NEF1 和输出格式保持。默认预览量程为 50 像素／250 ms，显式量程优先；浮点光流仍表示推理网格像素／输入窗口，没有乘以 1.25。
- 新增 `--result-mode inline|thread`，启动器对应 `E2FAI_RESULT_MODE`，默认 `thread`。测量默认仍关闭；本次测试显式开启。

## 最小验证与可比性

必要 CPU 检查全部通过：组窗 14 项，worker 14 项。覆盖 250 ms 半开边界、300 ms／300 ms+1 ns 断流、相同输出数组的灰度／彩图／浮点结果字节及顺序一致、归一化重置、两模式重连、结果队列满时 Stop、socket 阻塞发送后断开及取消计数。测量关闭测试未引入 CUDA 计时同步。容器构建和 Shell 语法检查通过。

只做三次各 10 秒回放和一次 30 秒真机采集，没有增加长测：

| 场景 | 窗长／模式 | 输入 | 全会话结果 | 过载／序号间断 |
|---|---|---|---:|---|
| 真机 RAW 回放 | 200 ms / inline | 同一 RAW 前 10 秒 | 39 | 无／无 |
| 真机 RAW 回放 | 250 ms / inline | 同一 RAW 前 10 秒 | 31 | 无／无 |
| 真机 RAW 回放 | 250 ms / thread | 同一 RAW 前 10 秒 | 31 | 无／无 |
| 现场相机 | 250 ms / thread | 30.007 秒采集 | 93 | 无／无 |

回放三组均为 **668 包、49,570,164 RAW 字节、9,024,739 解码事件**，播放速率 1；两组 250 ms 的已推理事件均为 8,781,434。RAW 内容、包序和间隔保持，只对包头纪元作固定平移。三个 GUI 画面均开启；回放使用 Qt 离屏渲染，现场使用可见 GUI。三组源码及镜像一致，只改变窗长和结果处理模式。模型均使用原有启动预热，不额外添加输入预热或排空阶段。

本次 `inline` 同样使用单次 CPU 快照，它是此次线程改造的串行对照，不是上一版重复复制的原函数。首次输入含真实记录中的解码时间回退，三组都在第一窗之前重置一次，不能把它当作新并行引入的差异。

回放输入平均约 **0.902 百万事件／秒**，明显低于此前一分钟现场的 8.786 百万事件／秒。因此本组对照能证明线程开销的转移，不能验证高负载下的持续饱和吞吐或保证不再过载。首次启动及关闭过程另有耗时，回放速率使用 `input_started.json` 的精确 10 秒区间，不能除以采集监控包含启动时间的 `elapsed_seconds`。

## 改造后实测

以下耗时单位为 ms。每窗推理线程占用由对应阶段实测合成：串行为“体素至 CPU 快照＋CPU 转图打包＋发送”，线程模式为“体素至 CPU 快照＋交接等待”，均不含组窗与等待新输入。

| 同一组 31 窗比较 | 250 ms 串行 | 250 ms 结果线程 |
|---|---:|---:|
| 推理线程占用均值／P95 | 152.32／156.55 | 126.42／129.47 |
| CPU 复制均值 | 0.86 | 1.00 |
| CPU 转图打包均值 | 22.85 | 22.84 |
| TCP 发送均值 | 3.25 | 3.29 |
| 输入 FIFO 驻留 P50／P95／P99 | 9.24／136.39／150.34 | 8.34／112.28／122.38 |
| 来源桥回调 → 灰度显示 P50／P95／P99 | 217.67／262.88／265.55 | 220.67／268.44／270.49 |
| 宿主模型进程平均 CPU | 79.66% | 80.66% |
| 模型进程显存峰值 | 2,264 MiB | 2,264 MiB |
| 整卡 GPU 平均使用率 | 42.6% | 36.0% |

结果线程交接等待平均 **0.015 ms**，结果 FIFO 驻留平均 **0.086 ms**、最大 **0.132 ms**，本段未出现结果消费者积压。输入 FIFO 驻留 P95 降低约 **17.7%**；但字节峰值由 5.12 MiB 到 5.44 MiB，没有显示所有队列指标一致改善。

各阶段串行执行成本合计仍约 **152.32／152.54 ms**，CPU 转图与发送工作并未消失。实际获得的是每窗推理线程释放约 26 ms，不能称为模型前向加速 17%。本段输入没有持续压满处理链路，未实测饱和吞吐上限。

**没有整体显示延迟改善的证据。** 灰度显示平均仅相差 +0.56 ms，P95 反而增加约 5.56 ms；GUI 约 100 ms 的刷新等待和单次短测相位差仍在。每组只有 31 个输出、10 个整卡 GPU 采样点，不能用 GPU 均值下降宣布效率提升。CPU 100% 表示一个逻辑核，结果线程 CPU 已包含在模型进程总量中。

### 现场 30 秒

全会话采集监控记录 **2,392 RAW 包、354,041,820 字节**；模型共接收 **2,444 批、162,695,100 事件**。不同订阅启动／关闭边界造成计数不同，不能直接相减宣布丢包。全会话生成 93 个结果，平均约 **3.10 次／秒**。

在估计的采集统计区间内，灰度显示有 92 个样本，来源桥回调至显示 P50／P95／P99 为 **244.66／300.51／315.86 ms**；模型进程平均 CPU **88.58%**，整卡 GPU 平均 **41.53%**。该延迟起点是最后贡献批的桥回调，终点是 setPixmap，不是物理传感器端到端延迟。

需区分统计区间与关闭阶段：区间内输入 FIFO 样本峰值 **22 批／50.99 MiB**；全会话停机前增长到 **36 批／190.22 MiB**，这些待处理数据在停止时清理。最后还有一窗前向完成但未发布，故全会话为 94 次推理、93 个结果。它的体素耗时约 **197.97 ms**，体素至 CPU 快照约 **321.44 ms**，显示高事件密度仍能形成长处理窗口。本次不能据“30 秒未溢出”推断更长时间也不会暂停。

现场未单独记录采集监控初始化的单调时钟；分析用“观察到 summary 的时刻减 30.007 秒”估计区间，约有 250 ms 轮询误差。完整会话摘要及区间统计均保留，避免把关闭阶段混作严格 30 秒峰值。所有测试都开启测量，未另做 ON/OFF 性能对照，记录与 CUDA 计时同步的扰动包含在结果内；本次分位数也不代表长时间稳定性。

## 时间配对的发现

适配器仅在测量开启时，每秒采一个 RAW 包，将序号、包头、回调单调／ROS 时钟及首末解码时间作为整数纳秒保存，不改变时间映射或事件顺序。

- 三组回放相同区间内，解码时间均推进 **6.425231 秒**，包头推进 **8.056751 秒**，与回调时钟的比例约 **0.7975**。
- 现场排除启动首包后，解码时间推进 **22.470910 秒**，包头推进 **28.177496 秒**、回调推进 **28.177478 秒**，比例 **0.797478**。
- 现场首包的首末解码时间从 **47.779649 秒回到 0.012244 秒**。时间回退计数在首包即出现，第一窗之前已重置；映射锚点按既有规则保留，因此会产生约 47.8 秒的基线偏差。它不是本次推理排队了 47.8 秒，也不是约 4,295 秒异常重新发生。

这把时间尺度差异定位到模型之前的解码输出／上游时间关系，不能由结果线程或 GUI 等待解释。250 ms 事件窗口仍约对应 313 ms 的墙钟供给节奏，解释了约 3.2 次／秒的输出供给。

尚未取得独立传感器时钟校准或原始 reference／子时间字的完整配对，不能进一步断言是解码单位错误还是更上游行为。本次没有插值、重新锚定或修复时间尺度。后续应先核对这一关系，再用映射时间评价物理延迟。
