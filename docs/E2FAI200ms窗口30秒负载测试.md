# E2FAI 200 ms 窗口 30 秒负载测试

测试时间：2026-09-14。数据目录：`output/window_200ms_30s_20260914_151834/`。

## 结论

200 ms 窗口可运行，但在本次高事件率真机输入下已经出现短时积压：30.026 秒内模型返回 109 个结果，发生 3 次新鲜度追赶并丢弃 95 个旧批次。平均 GPU 和内存仍有余量，主要风险是事件突发时的体素构建和推理链路尾延迟。因此 **150 ms 适合作为下一档受控测试值，100 ms 暂不适合作为默认值**。

## 配置与完整性

- 窗口：200 ms，原生 960×720，15-bin，不抽样事件。
- 模式：结果线程；性能记录开启；资源采样间隔 0.5 秒。
- RAW：2468 包、459,851,148 字节，30.026 秒，无序号间断，采集 PASS。
- 模型：113 个窗口完成推理，109 个结果完成返回；模型、桥接均无错误。
- 桥接：无丢弃，发送队列峰值 2 批 / 12,729,340 字节。
- 模型输入：收到 2522 批 / 268,643,045 事件；追赶丢弃 95 批 / 35,180,531 事件，3 个正在推理的旧结果失效。

## 缩短窗口判断

- **150 ms：值得测试。** 固定 CUDA 成本仍低于窗口对应的平均墙钟供给间隔，GPU 平均负载预计仍有余量；更少的单窗事件也可能降低体素构建耗时。但必须用至少 30 秒真机测试验证追赶次数和丢弃事件比例，不能只看平均 GPU。
- **100 ms：当前风险高。** 固定推理与 CPU 快照路径已接近或超过 100 ms，事件突发时明显超过；不先优化体素化、推理流水或降低输入尺寸/模型成本，容易形成持续积压。
- **低于 100 ms：当前链路不建议。** 即使显存充足，固定每窗计算成本也会限制输出率。

下一步建议测试 150 ms，并以“零追赶、零桥接丢弃、P99 最旧等待显著低于 500 ms、GPU P95 保持安全余量”为通过条件。若 150 ms 仍追赶，应先优化体素构建的尾延迟，再继续缩短窗口。
